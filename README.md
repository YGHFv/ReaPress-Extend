# 快递补全计划（ReaPress Extend）

快递补全计划（ReaPress Extend）是一个面向菜鸟、拼多多等快递通知链路的 LSPosed 扩展模块，用来补全快递在日常使用上的信息完整度：拦截并富化快递通知、维护独立的包裹首页、补全物流轨迹与驿站出库码。

## 功能概览

### 通知拦截与富化

- 拦截拼多多、菜鸟等来源的快递类通知，提取运单号、取件码、驿站名、快递状态等信息，替换为信息更完整的通知。
- 通知形态按设备能力探测，仅在确认系统权限可用时附加增强形态，避免拦截模式下丢通知。
- 揽件等静默状态的通知放行不拦截，但其中的信息照常落库。
- 通知原文与模块处理结果保留在模块内的「通知记录」页，可与首页数据分开清理。

### 快递首页

- 模块内置独立首页，按「到站包裹 → 派送中 → 运输中 → 其他 → 已签收/异常」分档展示。
- 到站包裹卡片单击查看详情、双击标记取件；运输中与已签收档内按最近更新时间倒序。
- 已完成超过 7 天的包裹自动移入「归档快递」二级页，首页底部保留入口。
- 详情页展示物流轨迹、驿站信息与身份码条码。

### 物流轨迹

- 复用宿主已登录的淘宝登录态向官方轨迹接口查询完整物流轨迹，模块不要求另行登录，也不伪造登录凭证。
- 只对已到站的包裹拉取轨迹，并做节流，避免无谓请求。
- 支持在宿主进程内自查包裹列表作为数据补充；宿主以常驻通知渠道进程存活时，也可由模块主动触发刷新。

### 身份码与出库条码

- 在菜鸟进程内借宿主自身的取件入口获取身份码，不仿签接口、不绕过访问控制。
- 身份码是平台属性，菜鸟与拼多多的码互不通用；驿站管理中可按驿站指定平台。
- 自绘 Code128-B 条码，详情页可直接出示给驿站自助机扫码。
- 指定平台无法取到身份码时如实提示，不悄悄回退到其他平台的码。

### 驿站规则

- 按驿站维护五类规则：驿站改名、取件码补全、地址补全、身份码来源、驿站指纹（坐标与 WiFi BSSID，支持在现场点「获取当前位置」采集）。
- 支持链式规则：A 改名为 B、B 改名为 C 时，A 按 A → C 生效。
- 地址信息优先使用宿主数据，手工填写兜底；「代收点」「快递柜」这类类型词不当作地址。

### 登录态复用

- 通过系统 CookieManager、本地 WebView cookie 库以及淘宝进程三个渠道读取既有登录态，取码动作只在宿主进程内完成。
- 不提供、不尝试伪造登录凭证。

### 其他

- 可选「隐藏后台卡片」：模块不进系统最近任务，每次回到前台自动重放该设置。
- 驿站排序规则在首页与驿站管理之间共用同一份比较器，两处顺序保持一致。

## 使用方式

1. 安装模块 APK。
2. 在 LSPosed 中启用模块，并勾选作用域：菜鸟、淘宝、拼多多。
3. 强制停止并重新打开上述应用，使 hook 生效。
4. 打开模块「快递补全计划」，首页会随通知与自查逐步补全数据。
5. 如需身份码功能，保持菜鸟可正常打开；驿站规则可在「驿站管理」中配置。

通知相关功能依赖系统通知权限；模块进程被系统回收后，宿主发出的广播会被静默丢弃，建议在系统设置中允许模块后台运行。

## 构建

需要：

- JDK 17
- Android SDK（compileSdk 37）

运行单元测试：

```
./gradlew :app:testDebugUnitTest
```

构建调试版：

```
./gradlew :app:assembleDebug
```

`local.properties` 需要指向本机 Android SDK，例如：

```
sdk.dir=C:/Users/<name>/AppData/Local/Android/Sdk
```

## 代码结构

- `core/`：纯函数（通知解析、状态分类、富化匹配、Code128 条码、地理计算），不碰系统时钟与 Android 依赖。
- `hook/`：宿主进程内的挂点与宿主上下文持有。
- `relay/`：模块进程与宿主进程之间的数据通道。
- `ui/`：Compose 界面，`ExpressUiKit.kt` 是视觉与组件的唯一权威。
- `notification/`：通知解析、投递与本地记录。

宿主内部类名只出现在 `hook/` 层；宿主升级后如出现功能失效，优先排查这一层。
