# 快递补全计划（ReaPress Extend）

快递补全计划（ReaPress Extend）是一个面向菜鸟、拼多多等快递通知链路的扩展模块，用来补全快递在日常使用上的信息完整度：拦截并富化快递通知、维护独立的包裹首页、补全物流轨迹与驿站出库码。

它有两条互相独立、可同时在线的数据链路：**LSPosed 模块**（hook 宿主，能力最全）与
**免 root 方案**（通知使用权 + 模块内自行登录，不依赖任何框架，见下文）。

## 功能概览

### 通知拦截与富化

- 拦截拼多多、菜鸟等来源的快递类通知，提取运单号、取件码、驿站名、快递状态等信息，替换为信息更完整的通知。
- 通知形态按设备能力探测，仅在确认系统权限可用时附加增强形态，避免拦截模式下丢通知。
- **按分类拦截无意义的动态通知**（设置 →「通知拦截」）：揽件、运输动态、派送、签收、其他提醒五类可分别勾选，勾上的分类不出现也不进包裹清单；Xposed 链路无法提交认证回传时保留原通知。
- 含取件码的通知，以及「到站取件」「投递异常」两类，始终保留，不受上面的分类开关影响。
- 揽件等静默状态的通知默认放行不拦截，但其中的信息照常落库；需要连它们一起清掉时，勾上「拦截揽件通知」。
- 通知原文与模块处理结果保留在模块内的「通知记录」页，可与首页数据分开清理。

### 快递首页

- 模块内置独立首页，按「到站包裹 → 派送中 → 运输中 → 其他 → 已签收/异常」分档展示。
- 到站包裹卡片单击查看详情、双击标记取件；运输中与已签收档内按最近更新时间倒序。
- 宿主自查、通知拦截与轨迹拉取补到新数据时，正在显示的首页会自动重读刷新，不必退出重进。
- 已完成超过 7 天的包裹自动移入「归档快递」二级页，首页底部保留入口。
- 详情页展示物流轨迹、驿站信息与身份码条码。

#### 菜鸟取件码后台同步（待真机验收）

- 新增菜鸟 **8.11.923** 的包裹联网同步适配：打开模块、首页下拉、自动轮查新一轮开始时，可静默唤醒菜鸟主进程，用其已有登录态同步包裹，再读取新取件码。不是仅重读旧缓存，也不需要启动菜鸟 Activity；**仍依赖 LSPosed、菜鸟主进程及有效登录态，不是免 root 能力**。
- 模块首页显示独立同步状态；“宿主联网同步完成”表示服务端游标已对齐、宿主数据库已确认、回传已提交，不代表所有广播都已送达模块。状态附完成时间，不承诺实时更新。
- 两端均有 5 分钟请求冷却；失败延后 10 分钟，风控至少退避 1 小时。单次最多查询一次版本游标、拉取 3 页增量，页间至少 2.5 秒；页数不足或库未就绪时如实失败，不强制重置库或扩大重试。
- 更新已有取件码要求完整运单号匹配、联网快照较新且宿主允许显示；保留旧码供核对。空码不擦除已有值，旧缓存/旧通知不能回退确认的新码。服务器尚未下发的码仍无法生成。
- 当前完成 MT MCP 静态分析与合成数据回归，未调用真实账号接口。其他菜鸟版本先保留缓存路径；安装后需让菜鸟进程重新加载模块代码，再验收后台同步与风控/登录失败路径。

### 物流轨迹

- 复用宿主已登录的淘宝登录态向官方轨迹接口查询完整物流轨迹，模块不要求另行登录，也不伪造登录凭证。
- 只对已到站的包裹拉取轨迹，并做节流，避免无谓请求。
- 支持在宿主进程内自查包裹列表作为数据补充；宿主以常驻通知渠道进程存活时，也可由模块主动触发刷新。

### 身份码与出库条码

- 在菜鸟进程内借宿主自身的取件入口获取身份码，不仿签接口、不绕过访问控制。
- 身份码是平台属性，菜鸟与拼多多的码互不通用；驿站管理中可按驿站指定平台。
- 自绘 Code128-B 条码，详情页可直接出示给驿站自助机扫码。
- 指定平台无法取到身份码时如实提示，不悄悄回退到其他平台的码。

### 驿站规则

- 按驿站维护五类规则：驿站改名、取件码补全、地址补全、身份码来源、驿站指纹（坐标与 WiFi BSSID，支持在现场点「获取当前位置」采集）。
- 支持链式规则：A 改名为 B、B 改名为 C 时，A 按 A → C 生效。
- 地址信息优先使用宿主数据，手工填写兜底；「代收点」「快递柜」这类类型词不当作地址。

### 登录态复用

- 通过系统 CookieManager、本地 WebView cookie 库以及淘宝进程三个渠道读取既有登录态，取码动作只在宿主进程内完成。
- 不提供、不尝试伪造登录凭证。

### 其他

- 可选「隐藏后台卡片」：模块不进系统最近任务，每次回到前台自动重放该设置。
- 驿站排序规则在首页与驿站管理之间共用同一份比较器，两处顺序保持一致。
- **打开模块自动补一次轨迹**：打开模块 / 首页下拉时，对首页上「到站 / 待取 / 派送中 / 运输中」的件主动拉一次全轨迹。
  宿主那张本地表不会因为被叫醒就变新（它得自己收到推送或用户打开菜鸟才会更新），所以以前的表现是「刷了跟没刷一样、必须点开某个件的详情才有新动态」。分批（一次最多 6 件）、按单号 5 分钟节流、批次间 1 分钟节流，仍受引擎自身的串行与风控退避约束。
- **备份与恢复**（设置 →「备份与恢复」，独立一页）：把包裹记录、通知记录、功能设置、驿站规则与免 root 登录态整份导出；支持**有变更时自动备份**、**定时备份**（系统不精确闹钟）、**保留份数上限**（超出从最旧开始删，只动本模块的文件）、**加密备份**（PBKDF2 + AES-GCM，密码只存本机）、**备份目录**（默认模块专属外部目录，也可自选任意文件夹）、**版本回退**（目录里的每一份都可直接恢复）与**本机快照**（每次恢复前自动留一份）。恢复前先把当前数据自动另存一份快照，再整份写回。备份文件里含有登录态，请只放在自己信得过的地方。

## 免 root 方案（工程补充方案）

模块原本只有一条腿：**寄生宿主**（要求装有 Xposed 框架并勾上作用域）。免 root 方案是第二条腿，
它靠用户可自行授予的**普通权限与自己的登录态**拿数据，作为 root 方案在环境不满足时的补充
（详见 [`docs/no-root-plan.md`](docs/no-root-plan.md)）：

- **通知使用权**（系统设置里授予一次，不需要 root）：模块内置通知监听服务，读白名单来源的
  通知原文，判定、落库、发通知走的是与 hook **完全相同**的一条链路 —— 首页、详情、归档、
  驿站规则全部通用。选定「拦截并替换」时，免 root 下用「出现后立刻撤掉」实现（可能有一帧
  闪烁，与 hook 的投递前拦截如实区分）。
- **模块内登录淘宝**：模块自己起 WebView 让用户登录一次，凭据只落在本机模块私有目录
  （不进日志、不上传）。之后模块自己就能查订单与全轨迹、商品图、驿站地址，**不必打开菜鸟、
  也不必勾作用域**。
- **自己发起同步**：淘宝订单 → 运单号 → 全轨迹 → 落库；「立即同步」可手动触发，开启自动轮查
  后每轮也会顺带发现新包裹。

同时在线时两条链路互补（hook 覆盖面更全，免 root 不挑环境），同一条通知只会提醒一次。

**免 root 下的边界**（界面上如实标注，不静默回退）：

- **身份码不可用**。那条接口只在 MTOP APP 通道开放，自登录的 H5 通道取不到。
- **拼多多只有通知文案**。它的接口签名在 native，不是换个 cookie 就能拿；
  通知里没有的字段（商品图等）补不了。
- **只有淘宝 / 天猫订单能被自动发现**。拼多多、别人寄来的件仍然依赖通知文案或宿主。

## 使用方式

### 有 root（完整能力）

1. 安装模块 APK。
2. 在 LSPosed 中启用模块，确认作用域包含系统框架（`system`）、菜鸟、淘宝、拼多多。
3. 在框架连接正常时先打开模块「快递补全计划」，初始化并向框架发布本次安装的回传认证凭据。
4. 重启设备，使 `system_server` 与宿主进程加载新代码；再打开上述应用。只重启宿主不能更新系统侧 hook。
5. 打开模块，首页会随通知与自查逐步补全数据。如需身份码功能，保持菜鸟可正常打开；驿站规则可在「驿站管理」中配置。

通知相关功能依赖系统通知权限；部分 ROM 的后台限制仍可能阻止广播投递，建议在系统设置中允许模块后台运行。发送成功只表示广播已提交，不等于接收、持久化或通知展示成功。

### 免 root

1. 安装模块 APK（不需要装 Xposed）。
2. 打开模块 → 设置 →「免 root 采集」打开，并按提示在系统设置的「通知使用权」里勾上本模块。
3. 到设置 →「免 root 模式」→「登录淘宝」登录一次（用于自己拉订单与轨迹）。
4. 首页下拉刷新，或在该页点「立即同步」。
5. 想让它后台自动更新时，在设置 →「自动轮查」里开启（会常驻一条通知）。

两种方式可以同时使用，界面上的「免 root 模式」页会显示当前实际的数据来源。

免 root 的替换通知先检查应用通知开关、权限、渠道和渠道组；投递失败不占用成功去重名额，也不撤原通知。重复事件只有在同一事件的替代通知仍然存在时才撤原通知，查询失败或已被用户清除则保留。系统接受 `notify()` 不代表所有 ROM 都已实际展示；root 侧仍没有端到端投递确认。

### 跨进程回传与升级

- 系统/宿主回传统一经过认证发送器；模块的导出接收器先验证安装级 256 位随机凭据，再检查 action、字段类型与大小。显式组件名和 action 名称本身不是认证。
- 凭据仅存模块私有配置，并通过框架托管的 RemotePreferences 提供给被注入进程；不写日志、不进入导出文件或恢复前快照，恢复备份不能替换它。清除模块数据或重装后须重新打开模块发布新凭据。
- 升级后必须重启旧注入进程；不兼容无凭据的旧回传，也不会为兼容旧版本开放未认证入口。凭据尚未就绪或发送失败时保留原通知，富化失败保留后续重试机会。
- 这是受信注入进程共享的凭据，不是逐宿主 UID 认证，也不提供防重放；不防护 root、框架或受信宿主本身被控制的情况。仅使用免 root 链路不需要框架凭据。

### 复位与恢复行为

- 看门狗复位使用一次性请求 ID；框架重连只重发同一 ID，系统侧登记消费，不能因反复保存设置而永久绕过熔断。新一轮连续两次启动失败仍会停用 hook；保护状态无法可靠保存时也不安装系统 hook。
- 框架初次连接或重连会完整同步本地设置；离线修改不必再手动保存一次。被注入进程只读取框架配置，不尝试修改只读 RemotePreferences。
- 恢复备份会重载 Cookie、配套 UA 与风控状态，同步框架设置，启停/重载轮查并刷新界面；空登录态会清空旧缓存，旧备份不能缩短当前风控退避。
- 写回失败会尝试回滚已写入的存储，并保留恢复前快照；回滚未确认或系统拒绝服务启动会明确提示，不冒充完全成功。复位请求、回传认证凭据和本机备份目录/密码均不从备份导入。
- 定时备份由不精确闹钟提交系统 JobScheduler，JobService 的完成回调覆盖实际写盘；不使用额外第三方调度依赖。最后成功时间与尝试时间分开保存，失败后推进下次定时尝试，有变更触发也遵守十分钟冷却，重复排队与手动/自动并发会被合并或拒绝。系统后台限制仍可能推迟任务；SAF 中断、进程被杀与备份文件原子写入尚无完整保证。
- Android 系统自动备份及设备迁移均显式排除模块数据（含登录态和安装认证凭据）；模块自己的手动导出/恢复不受影响，换机请使用可信位置的加密导出文件。厂商迁移工具是否遵循规则仍需设备核验。
- 淘宝登录 WebView 保留 JavaScript 和 HTTPS 跨域验证；禁用文件/内容提供器访问、明文混合内容和原生 scheme 跳转，证书错误不放行，关闭页面后销毁视图。若验证流程必须跳转外部应用，当前会被阻止，需另行设计受控跳转，不以关闭安全检查兜底。

## 构建

需要：

- JDK 17
- Android SDK（compileSdk 37）

运行单元测试：

```
./gradlew :app:testDebugUnitTest
```

构建调试版：

```
./gradlew :app:assembleDebug
```

`local.properties` 需要指向本机 Android SDK，例如：

```
sdk.dir=C:/Users/<name>/AppData/Local/Android/Sdk
```

## 代码结构

- `core/`：不依赖 Android 的核心逻辑（通知解析、状态分类、富化匹配、Code128 条码、地理计算、免 root 能力判定、备份文件编解码与加密），以及可离线测试的请求状态、队列、订单批次和回传凭据逻辑；请求编排的时钟、执行器和网络操作由调用方注入。
- `backup/`：备份的执行、加密、目录抽象与自动/定时调度（`core/BackupBundle`/`core/BackupCrypto` 负责格式，这里负责落地）；导出、恢复/回滚与相关存储写入共用事务锁，`BackupRestoreRuntime` 协调恢复后的缓存、配置及服务状态。
- `hook/`：宿主进程内的挂点与宿主上下文持有，`AuthenticatedRelaySender` 是系统/宿主回传的统一发送出口。
- `config/`：本地权威设置与框架投影；复位请求独立于普通设置，消费状态由 `core/WatchdogStateMachine` 和系统侧 `WatchdogStateStore` 管理。
- `noroot/`：免 root 方案（通知监听服务、能力探测）—— 不依赖 Xposed。
- `relay/`：模块进程与宿主进程之间的数据通道；`RelayIngress` / `RelayPayloadPolicy` 负责认证与载荷校验，`RelayCredentialStore` 负责凭据持久化及框架发布。
- `ui/`：Compose 界面，`ExpressUiKit.kt` 是视觉与组件的唯一权威。
- `notification/`：通知解析、投递与本地记录；`ExpressRecordStore` 在模块进程内用同一把可重入锁保护完整读改写、清空与恢复，防止并发更新互相覆盖。

宿主内部类名只出现在 `hook/` 层；宿主升级后如出现功能失效，优先排查这一层。

事务锁用于模块进程内协调，不是跨进程锁或崩溃安全数据库事务；多文件写回期间断电、已经在途的网络回执及 ROM 服务限制仍需设备验收。审计基线、已修复项、验证结果及待办见 [项目自检报告](docs/project-self-check-2026-09-29.md)。
